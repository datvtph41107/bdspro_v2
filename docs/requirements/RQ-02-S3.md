# RQ-02A.02-S3 — Registration & Security Policies
Status OPEN. Current user selections: email/password/display_name required; account-centric; own response four fields. Initial method email/password; phone/Google/invitation deferred. No product validation. The first local health task is independent; before auth code, review these policies in order. Each question includes why, scenario, tradeoff, acceptance and source.

## S3.01 — Email/admission and activation (IND-R02/R03)
Why: knowing a password for a newly created account does not prove ownership of submitted email. Scenario A registers B's address; B must not lose legitimate access or have their identity taken. Options: verify before normal account activation (recommend); limited pending session only for verification/resend (more policy/route guards); no verification not acceptable for reliance on email. Define pending expiry/re-registration, collision/resend, email canonicalization policy (do not assume all providers treat aliases/case equally), verification challenge binding to account/email, single-use and expiry, safe response to duplicate/invalid. Acceptance wrong/expired/replayed/cross-account denied, no unauthorized activation, recover from failed delivery. Choose no exact TTL yet. Reference [OWASP email verification](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html).
## S3.02 — Password (IND-R04)
Why: stolen DB and guessing. Compare Argon2id (recommended for new app per OWASP), bcrypt (existing practice, input limit and cost), use library rather than own algorithm. Need length/Unicode/size limits, compromised password policy, resource cost calibration, safe errors, secret handling, hash migration and tests. Do not select arbitrary cost or log passwords. [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [NIST 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html).
## S3.03 — Session and client (IND-R05)
Why: login once, many requests, logout. First determine frontend origin/topology and mobile need. Compare opaque random server-side session (recommend for browser-only if suitable), JWT+DB session, stateless JWT (cannot revoke instantly alone). Cookie vs bearer is separate transport choice; for cookies require secure attributes, CSRF policy and HTTPS before real use. Decide expiry/idle timeout/multiple devices, current/all logout and restart semantics, token secret storage. Acceptance invalid/expired/revoked denied, logout old credential fails later requests, no leaking secret. [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
## S3.04 — Abuse, recovery, external failure (IND-R03/04/07)
Why: attacks against account from multiple IPs and email flood, lost password, DB/mail outage. Compare in-memory, PostgreSQL and Redis against actual policy, restart, multi-instance and load; no Redis chosen. Define limits per account and source, privacy-safe responses, trusted proxy boundaries, delivery retry/resend, recovery token one-use expiry and session invalidation; no silent fail-open. No queue/outbox until durability requirement. [OWASP authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [Forgot password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
## S3.05 — HTTP/API contract and authorization (IND-R06/07)
Proposed POST /api/v1/auth/register, POST /api/v1/auth/login, GET /api/v1/me, POST /api/v1/auth/logout plus verify/resend/recover endpoints to agree. Define success/error/status/JSON, content type/body limit, allowed fields and ID type (bigint JSON precision), no mass assignment. /me derives identity from trusted verified session, not body/header/query account ID; no credential output. A/B cross-account negative case. [OWASP API1](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/), [API3](https://owasp.org/API-Security/editions/2023/en/0xa3-broken-object-property-level-authorization/).
